# 쿠팡 물류 네트워크 지도

전국 쿠팡 물류시설 288곳의 위치와 목록입니다. 배경지도는 OpenStreetMap을 씁니다.

**지도 보기 →** `https://<깃허브아이디>.github.io/<저장소이름>/`

| 유형 | 개수 | 표식 |
|---|---:|---|
| 풀필먼트 센터 | 88 | 빨강 사각형 |
| 서브FC | 32 | 보라 마름모 |
| 서브허브 | 51 | 주황 삼각형 |
| 캠프 | 114 | 청록 원 |
| 기타 시설 | 3 | 회색 십자 |

## 파일 구조

```
index.html        공개되는 페이지 (build.py 가 자동 생성)
facilities.csv    원본 데이터. 수정은 여기서만
template.html     페이지 디자인과 기능
build.py          facilities.csv + template.html → index.html
geocode.py        주소 → 좌표 (카카오 로컬 API)
geocode_osm.py    주소 → 좌표 (Nominatim, API 키 불필요)
```

## 데이터 고치는 법

깃허브 웹에서 `facilities.csv` 를 열어 연필 아이콘으로 수정하고 커밋하면 끝입니다.
GitHub Actions 가 `index.html` 을 다시 만들어 커밋하므로 로컬에서 아무것도 돌릴 필요가 없습니다.
1~2분 뒤 페이지에 반영됩니다.

로컬에서 작업하실 때는 이렇게 합니다.

```bash
python3 build.py facilities.csv index.html
```

### CSV 열

| 열 | 설명 |
|---|---|
| `name` | 시설명 |
| `type` | `풀필먼트센터` / `서브FC` / `서브허브` / `캠프` / `기타` |
| `address` | 주소 |
| `region` | 원본 목록의 권역 구분 |
| `sido`, `sigungu` | 비워 두면 주소에서 자동으로 채워집니다 |
| `lat`, `lng` | 위경도. 비어 있으면 표에만 나옵니다 |
| `precision` | 좌표 정밀도. 비어 있으면 정확한 좌표로 취급 |
| `note` | 비고 |
| `source_url` | 출처 링크. 넣으면 팝업에 표시됩니다 |

엑셀로 편집하실 때는 **CSV UTF-8** 로 저장하세요. 일반 CSV 는 한글이 깨집니다.

## 좌표 정밀도

`precision` 열이 좌표를 **어떻게 얻었는지** 기록합니다. 값이 비어 있을 때만 믿을 수 있는 좌표입니다.

| 값 | 뜻 | 신뢰도 |
|---|---|---|
| (빈칸) | 주소를 그대로 조회해 찾음 | 믿을 수 있음 |
| `축약주소` | 주소가 안 잡혀 뒷부분을 잘라내고 찾음 | **확인 필요** |
| `키워드` | 주소가 안 잡혀 시설명으로 장소 검색함 | **확인 필요** |
| `읍면동` / `시군구` | 행정구역 중심점. 지오코딩 전 임시값 | 부정확 |
| `실패` | 어떤 방법으로도 못 찾음. 좌표 없음 | 손으로 채워야 함 |
| `주소없음` | 원본에 주소가 없어 지도에서 제외 | — |

`matched` 열에는 카카오가 실제로 찾아낸 주소가 들어갑니다.
원본 `address` 와 비교하면 어디서 어긋났는지 바로 보입니다.

페이지 상단 **좌표** 칸에서 `확인 필요만` 을 고르면 검증할 시설만 추려 볼 수 있습니다.

### 좌표 다시 채우기 (브라우저에서)

1. [카카오 개발자센터](https://developers.kakao.com) → 내 애플리케이션 → 애플리케이션 추가하기
2. 만든 앱의 **요약 정보 → 앱 키**에서 `REST API 키` 복사
3. 이 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   이름 `KAKAO_KEY`, 값은 복사한 키
4. **Actions → 좌표 채우기 → Run workflow**
   - **어떤 행을 다시 찾을까요**: `전체-다시찾기` (기본값)
   - **어떤 지오코더를 쓸까요**: `kakao`

`전체-다시찾기` 는 기존 좌표를 모두 지우고 288개를 처음부터 다시 찾습니다.
좌표를 손으로 고쳐 둔 것이 있다면 `비어있는-행만` 을 고르세요.

실행이 끝나면 로그의 **결과 요약** 단계에 상태별 개수와,
확인이 필요한 시설의 `원본 주소 / 실제로 찍힌 곳` 이 나란히 출력됩니다.

## 같은 건물에 있는 시설

같은 주소를 쓰는 시설이 53곳 120개 있고, 한 지점에 최대 18개까지 몰려 있습니다.

표식은 핀 모양이고 **핀의 뾰족한 끝이 실제 좌표를 가리킵니다.**
같은 좌표의 시설들은 좌표를 그대로 둔 채 화면상 위치만 조금씩 밀어 카드 부채처럼 겹쳐 꽂았습니다.
밀어내는 단위가 위경도가 아니라 화면 픽셀이라, 지도를 확대하든 축소하든 겹침 정도가 항상 같습니다.
핀마다 11px 정도가 드러나 있어 하나씩 눌러 구분할 수 있고, 마우스를 올리면 그 핀이 맨 앞으로 올라옵니다.

겹침 정도를 바꾸려면 `template.html` 위쪽의 세 값만 고치면 됩니다.

```js
const PIN_SIZE = 27;     // 핀 크기(px). 다섯 유형 모두 같은 크기
const FAN_X = 11;        // 옆으로 밀어내는 간격(px). 키우면 덜 겹칩니다
const FAN_Y = 23;        // 줄을 바꿀 때 위로 올리는 간격(px)
const FAN_PER_ROW = 6;   // 한 줄에 몇 개까지 놓을지
```

## 핀 모양과 색

유형 구분이 색 하나에만 의존하지 않도록 핀 머리 안에 기호를 함께 넣었습니다.

| 유형 | 색 | 기호 |
|---|---|---|
| 풀필먼트 센터 | 빨강 | 사각형 |
| 서브FC | 보라 | 마름모 |
| 서브허브 | 주황 | 삼각형 |
| 캠프 | 청록 | 원 |
| 기타 시설 | 회색 | 십자 |

`template.html` 의 `TYPES` 배열에서 `color`, `shape`, `PIN_W` 의 크기를 바꿀 수 있습니다.
`shape` 는 `square`, `diamond`, `triangle`, `circle`, `plus` 중에서 고릅니다.
